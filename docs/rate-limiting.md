# Rate limiting deployment checks

The backend applies a public limit of 100 requests per 15 minutes per client IP, a login limit of 10 attempts per 15 minutes per client IP, and a feedback/rating limit of 30 writes per minute per authenticated account. These are starting policies, not measured capacity guarantees. Counters use separate environment/policy key prefixes. Responses over a limit return 429 with retry metadata. Cheap `/api/health` liveness is excluded from the user quota; protect it at the deployment edge if it needs abuse controls.

Production requires the configured Upstash REST URL and token and a working shared Redis store. Missing configuration or an initialization/command failure returns 503 for protected requests. It does not silently switch to process memory. `RATE_LIMIT_MODE=memory` is allowed only for local development/tests; set it explicitly in local `.env`. Set `RATE_LIMIT_MODE=redis` for production or staging, and keep the Upstash credentials on the backend only.

`TRUST_PROXY_HOPS` is 0 by default and accepts 0, 1, or 2. Set it to the number of proxy hops that the actual deployment has proved trustworthy. Do not use `true` or trust arbitrary forwarded addresses. With 0, a client supplied `X-Forwarded-For` cannot change the rate key; a deployment with a trusted ingress may need a measured nonzero value so distinct clients are not collapsed into the same key.

Before release, use a staging deployment and a separate `RATE_LIMIT_NAMESPACE` (for example `staging-check`) on the shared Upstash account. Send harmless requests from two distinct client addresses, then attempt to spoof `X-Forwarded-For`; verify the intended rate keys, 429 and retry headers, and shared counts across two instances. Repeat with the Upstash store unavailable and verify 503 plus an operator-visible error. Use a small test request count and a namespace not shared with production users. The local suite tests a stubbed shared adapter and a nontrusted forwarding header; it does **not** verify the real ingress or Upstash account.
